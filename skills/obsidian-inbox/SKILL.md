# Obsidian 知识库入库流程

> 本技能由 `dsh-obsidian-inbox` 插件提供。**vault 路径与主目录分类由插件配置决定**：
> vault 路径来自插件 Config 的 `defaultVault`（**默认空**，需在插件配置里设为你的库路径），
> 主目录分类需按你自己的库调整（见下文）。

## 唯一 vault（不可变）

- vault 路径：**插件配置 `defaultVault`**（默认空，需配置为你的库路径）。用**工具** `obsidian_validate_vault` 校验时可传 `vault` 参数覆盖。
- 路径不存在或无权限时立即停止，不自动创建另一个库。
- 授权只针对相关笔记；不修改 Obsidian 设置、不安装插件、不整理整个库。

## 第一步：授权判断（先做）

| 用户说法 | 行为 |
| --- | --- |
| 整理入库 / 保存这个结论 / 记录为错题 / 记录为项目 / 更新已有笔记 | 允许有限写入 |
| 这个值得保存吗？ | 只分析，不写 |
| 不要入库 | 完全不修改 vault |

## 第二步：写入前先检索（顺序固定）

1. 相似文件名
2. aliases 与现有 Wiki 链接
3. frontmatter（tags / type / topic）
4. 标题与正文
5. 导航页（MOC）

必须读过候选笔记内容，不能只凭文件名决定合并还是新建。

## 第三步：只提炼长期价值

保留：结论、解释、决定、用户自己的理解、可复用步骤、错误原因、下一步。

不保存：完整聊天、寒暄、临时排障噪音、密码、令牌、无必要的个人信息。

笔记脱离原对话后必须能独立读懂。

## 第四步：按未来检索位置分类（一个主归属）

判断标准不是“现在属于什么话题”，而是“用户下次解决同类问题时最可能去哪里找”。

主目录（**按你自己的库改**）：

- `00_收件箱`（未整理暂存）
- `01_考研`
- `02_AI与编程`
- `03_智能制造`
- `04_项目`
- `05_想法`
- `06_错题`
- `07_对话精华`

每个知识只选一个主目录；跨领域关系用链接和标签表达，不复制多份。

## 第五步：合并优先于新建

- 同一核心问题：更新已有笔记。
- 不同未来检索目的：才新建笔记。
- 保留原 `created` 和用户文字，只更新 `updated` 及相关章节。
- 文件名用明确概念或问题，不用“对话1”“GPT总结”之类名称。
- 只做局部编辑（edit），避免整篇覆盖（write）。

## 第六步：两级确定性校验（写后必跑）

### 第一层：公式

- 行内公式只用 `$...$`。
- 块公式用单独成行的 `$$...$$`。
- 拒绝 `\(...\)`、`\[...\]`、未配对的 `$`。
- 表格行内公式不能出现裸 `|`。
- 图片中的公式保留可编辑 Markdown。

### 第二层：结构与链接

- `.obsidian` 顶层 JSON 能解析。
- `[[Wiki Links]]` 目标存在。
- 无同名笔记导致的链接歧义。

校验方式（用**插件工具**，不是 shell 脚本）：

```text
obsidian_validate_vault  → 校验当前配置的 defaultVault
obsidian_validate_vault  (vault: "D:/your/vault")  → 校验指定 vault
```

返回 `{ ok, noteCount, problems }`；`ok=false` 时逐条修复并重跑直到通过，校验不通过不得宣布“已入库”。

## 第七步：验证失败不能冒充成功

- 只修复本次操作引入的问题。
- 不因全库检查发现历史问题就顺手大规模改库。
- 校验不通过，不得宣布“已入库”。

## 设计原则（优先级从高到低）

1. 检索优先于归档。
2. 合并优先于复制。
3. 一个主归属，其他关系用链接。
4. LLM 负责语义判断，脚本负责确定性检查。
5. 重复执行同一请求，更新同一笔记，不生成副本。
6. 不覆盖用户内容；不虚构来源、任务链接或引用。
7. 校验不通过，不宣布“已入库”。
